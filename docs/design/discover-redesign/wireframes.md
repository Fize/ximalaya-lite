## 1. 目标与非目标

### 目标

1. 把「发现」从“6 个关键词的搜索结果”改成官方五域浏览：**推荐 / 分类 / 广播 / 榜单 / 主播**。
2. 任何入口点到内容后，都能在**本 App 内完成播放**（不跳官方 App、不跳浏览器）。
3. **所有页面零广告**：不渲染 `ad` 模块，不新增开屏/插屏/横幅/激励视频，不展示会员促销位。
4. 推荐流是否个性化，**可在设置中开关**（见 §10）。

### 非目标

- 不改「收听」「我的」两页的现有结构（除设置页新增一节）。
- 不做打赏、充值、支付、会员购买入口（沿用 README 的既有取舍）。
- 不做离线下载、不做评论体系改造。
- 不做视觉皮肤/主题改造；本期只交付结构与交互。

## 2. 数据约束（实测，2026-11-26）

| 域 | 接口 | 实测结果 | 结论 |
|---|---|---|---|
| 发现 tab 配置 | `mobile.ximalaya.com/mobile/discovery/v1/tabs` | 200，5 个 tab：推荐/分类/广播/榜单/主播 | 结构可对齐官方 |
| 推荐 | `.../discovery/v1/recommend/album?device=android&pageId=1&pageSize=6&includeActivity=false&includeSpecial=false` | 200，模块：`focus` `square` `guessYouLike` `ad` `playlist` `live` `categoriesForExplore` `cityCategory` `recommendAlbum` | 可用；`pageId` 只是**轮换**（第 1/2 页 6 条中 5 条重复），不能当无限流 |
| 分类树 | `www.ximalaya.com/revision/category/allCategoryInfo` | 200，5 个分组 / 28 个内容分类（如「历史」） | 可用 |
| 分类结果 | `m.ximalaya.com/m-revision/page/category/queryCategoryPage?categoryCode=lishi&page=1` | 200；该分类下另有 24 个子类（正史/野史/军事…）；`pageSize=20`、`totalCount=1000`、`sort=0/1/2` 均可用；5 个筛选维度（节目形式/主播/年代/是否完本/是否付费） | 可用，支持分页 + 排序 + 筛选 |
| 广播（列表） | 推荐流 `live` 模块 | 字段：`roomId` `name` `nickname` `playCount` `status` `cover*` `categoryName` `tingUrl` | 列表可用 |
| 广播（播放） | 未定位到推流接口 | `live.ximalaya.com/*` 全部 404/403 | **风险**，见 §13 Q1 |
| 榜单 | `m.ximalaya.com/m-revision/page/rank/queryRank?clusterCode=&categoryCode=` | 接口存在；有效 `clusterCode` 未知（传值被忽略返回空） | **参数待枚举** |
| 主播 | 未找到列表接口 | `recommend/anchor` 返回的是专辑流，不是主播；`queryAnchorDetail` 等 404 | **缺口**，见 §13 Q2 |
| 听单 | 推荐流 `playlist` 模块（`specialId`） | 列表字段可用；详情接口未验证 | 风险，可降级隐藏模块 |
| 播放 | 现有 `ContentApi.resolve` + `PlaybackService` | 已实现免费/授权/VIP/付费判定与播放 | 复用，无需改动 |

**推导出的硬约束**

- 推荐页不能做“无限下滑加载更多”，只能**换一换**（`pageId` 轮换）。
- 分类页可以做真分页 + 排序 + 筛选。
- 推荐流里的 `guessYouLike` 项**没有主播名**（字段里无 `nickname`），卡片副行必须容忍缺字段；`categoriesForExplore` / `cityCategory` / 分类页有 `anchorInfo.nickname`。
- `ad` 模块必须过滤；`focus` / `square` 只在内容型条目时渲染。

## 3. 信息架构

```
底部导航（不变）
└─ 发现
   ├─ 搜索（现有页面，从标题栏 ⌕ 进入）
   ├─ 推荐（默认 tab）
   │  ├─ 猜你喜欢（专辑卡网格，换一换）
   │  ├─ 分类模块「相声评书」等（横滑专辑卡 → 分类结果页）
   │  ├─ 正在直播（横滑直播卡 → 直播间）
   │  ├─ 精品听单（横滑听单卡 → 听单详情）※接口未验证，失败则整块不渲染
   │  └─ 为你推荐（有数据才渲染）
   ├─ 分类
   │  ├─ 分类网格（5 个分组 × 28 个内容分类，chips 换行）
   │  └─ 分类结果页
   │     ├─ 子类 chips（如历史：正史/野史/军事…）
   │     ├─ 排序（综合/最热/最新）
   │     ├─ 筛选（节目形式/主播/年代/完本/付费）
   │     └─ 专辑列表（分页 20/页 → 专辑页）
   ├─ 广播
   │  ├─ 分类 chips（脱口秀/声优CV/情感/音乐…）
   │  └─ 直播列表（分页 → 直播间 → 播放）
   ├─ 榜单
   │  ├─ 榜单组 chips（热播/新晋/畅销/口碑…，以接口返回为准）
   │  ├─ 分类筛选
   │  └─ 榜单列表（名次 → 专辑页）
   └─ 主播
      ├─ 推荐主播列表
      └─ 主播详情（TA 的专辑 → 专辑页）

我的 → 设置 → 内容偏好 → 个性化推荐（开关）
```

**导航层级**：发现（L1）→ 分类结果/直播间/听单/榜单/主播详情（L2）→ 专辑（L3）→ 播放器（L4）。
沿用现有 per-tab 返回栈，L2/L3 进入后底部导航保留。

## 4. 用户流程

### F1 冷启动 → 推荐 → 播放（主流程，逐步状态）

| 步 | 用户动作 | 界面 | 状态 | 失败分支 |
|---|---|---|---|---|
| 1 | 点「发现」 | 推荐 tab | 有缓存：立即显示缓存 + 静默刷新；无缓存：3 个模块骨架 | 全失败 → 空态「推荐内容加载失败」+ 重试 |
| 2 | 上下滑 | 模块列表 | 模块按服务端顺序；`ad` 不渲染 | 单模块失败 → 该模块位置显示 1 行「该部分加载失败，重试」 |
| 3 | 点专辑卡 | 专辑页 | 立即进入，标题/封面用卡片已有数据占位，节目列表 loading | 加载失败 → 内联「加载失败，重试」，保留标题封面 |
| 4 | 点「播放」 | 播放器 | 无历史 → 第 1 集；有本机进度 → 从续播点 | 付费/无权限 → 既有权益提示，停留专辑页 |
| 5 | 收起播放器 | 回专辑页 → 返回 | 恢复滚动位置 | — |

### F2 分类 → 筛选 → 播放

发现 → 分类 → 网格中点「历史」→ 子类「正史」→ 排序「最新」→ 筛选「是否完本＝完结」→ 专辑 → 播放。
进入分类结果页默认「全部」子类 +「综合」排序 + 无筛选；切换分类或子类时列表回顶并取第一页（400ms 内只发最后一次请求）。

### F3 广播 → 直播间 → 播放

发现 → 广播 → 点直播卡 → 直播间（进入即请求推流并播放）→ 暂停/继续 → 返回。
失败：`正在连接直播…`（可取消）→ 15s 超时 → `暂时无法连接该直播` + 重试 / 返回。

### F4 榜单 → 专辑 → 播放

发现 → 榜单 → 切榜单组 → 点第 N 名 → 专辑页 → 播放。名次仅展示，不改变点击目标。

### F5 主播 → 详情 → 播放

发现 → 主播 → 点主播卡 → 主播详情（简介 / TA 的专辑）→ 专辑 → 播放。

### F6 关闭个性化

我的 → 设置 → 内容偏好 → 关闭「个性化推荐」→ Snackbar「已关闭个性化，将显示通用内容」→ 回发现：推荐流清空并重新请求（不带身份）。

### F7 离线

进入发现：有缓存 → 显示缓存 + 顶部 `离线，显示上次内容`（不遮挡内容）；无缓存 → 空态 + 重试。任意 tab 的刷新失败都保留旧内容。

## 7. 交互规格

### 导航与状态保持

- 顶级 Tab 切换：内容交叉淡入 150ms；每个 Tab 独立 `LazyGridState`，切回保持位置。
- Tab 首次进入才请求；已有缓存先渲染缓存。
- 进入 L2/L3 后返回：恢复来源页滚动位置（沿用现有 `AlbumReturnState` 思路，扩展到分类/榜单/主播页）。
- 系统返回：逐级 pop；播放器为独立栈项，收起回来源。

### 刷新与分页

| 页面 | 刷新 | 分页 |
|---|---|---|
| 推荐 | 下拉刷新（`pageId+1` 轮换整页）+ 标题栏「换一换」（同刷新，滚回顶部） | 无（接口只轮换，不做无限流） |
| 分类结果 | 下拉刷新 | 触底加载 `page+1`，20/页 |
| 广播 | 下拉刷新 | 触底加载 20/页 |
| 榜单 | 下拉刷新 | 触底加载（若接口支持） |
| 主播 | 下拉刷新 | 触底加载 20/页 |

- 触底预取阈值：距末尾 3 项。
- 分页中：底部 48dp 进度行；失败：`加载失败，点击重试`（保留已加载内容）；结束：`已显示全部`。
- 请求代际（generation）：切 tab / 切分类 / 改筛选立即取消旧请求，丢弃迟到结果。

### 点击规则

| 目标 | 行为 |
|---|---|
| 专辑卡 / 榜单行 / 分类行 | 进专辑页（不直接播放，避免误播与流量） |
| 专辑页「播放」 | 续播点 → 第 1 集；权限不足弹既有提示 |
| 直播卡 | 进直播间并**自动起播**（直播没有选集，点击即收听意图） |
| 听单卡 | 进听单详情；「播放全部」= 第 1 张专辑第 1 集 |
| 主播卡 | 进主播详情 |
| 「换一换」 | `pageId+1` 重拉整页模块并整体替换，滚动回顶，交叉淡入 150ms |
| 「全部 ›」 | 分类模块 → 对应分类结果页；直播模块 → 广播 tab；听单模块 → 听单列表页 |

### 直播交互

- 进入直播间自动起播；播放按钮为 播放/暂停 双态。
- 连接中：按钮位显示 `正在连接直播…` + 取消（48dp）。
- 15s 无首帧：`暂时无法连接该直播` + 重试 / 返回。
- 直播流不支持进度条、倍速、跳过头尾；播放器进入直播态时隐藏这些控制（见 §13 Q1）。
- 退出直播间：停止直播播放，恢复原有专辑队列的暂停状态（不自动续播旧内容）。

### 动效

- 列表项无入场动画（避免每次刷新闪烁）；骨架 shimmer 1200ms。
- 系统「减少动画」开启时：关闭 shimmer 与交叉淡入，仅保留 100ms 透明度变化。

### 无障碍

- 所有图标按钮必须有 `contentDescription`；LIVE 状态必须有文字，不能只靠颜色。
- 卡片与行使用 `Role.Button`；列表使用 `heading()` 标注分区。
- 骨架屏期间 `contentDescription = "正在加载"`，完成后移除。
- 错误提示使用 `liveRegion = Polite`（沿用现有 `InlineNotice`）。

## 10. 个性化推荐：能否做成设置项？

**结论：能，建议做成本地开关，默认开启（登录态生效）。**

### 方案

- 位置：`我的 → 设置 → 内容偏好 → 个性化推荐`（W-10）。
- 开启：推荐请求携带账号身份（现有 Cookie/凭证），使用账号缓存键 `recommend:{uid}`。
- 关闭：推荐请求**不带账号身份**（匿名请求），使用独立缓存键 `recommend:anon`，并清空内存中的个性化推荐缓存。
- 未登录：开关禁用，说明「登录后可开启个性化推荐」；推荐流按匿名请求。
- 切换后不重启：立即清缓存 → 重新拉取 → Snackbar 提示。

### 诚实性约束

- 官方推荐接口**没有**显式的“关闭个性化”参数（已探测，未见 opt-out 参数），因此本方案是「以匿名身份请求 → 得到通用热门内容」。
- 匿名请求仍可能受 IP/设备等聚合因素影响，所以文案写「通用热门内容」，**不承诺**“完全不个性化”。
- 该开关只影响发现-推荐的请求身份；**不影响**账号历史同步（历史同步是独立能力）。文案中不暗示会关闭同步。

### 文案

| 场景 | 文案 |
|---|---|
| 设置项标题 | 个性化推荐 |
| 副行（开） | 按收听记录推荐专辑和主播 |
| 副行（关） | 关闭后使用通用热门内容 |
| 未登录 | 登录后可开启个性化推荐 |
| 切换 Snackbar | 已关闭个性化，将显示通用内容 / 已开启个性化推荐 |

### 验收

- 关闭后，推荐请求不携带 `uid`/Cookie（测试可断言）。
- 关闭后缓存键切换，不与登录态缓存串用。
- 未登录时开关不可操作但有解释文案（Nielsen #1 系统状态可见）。

## 11. 零广告规则（硬约束）

1. `moduleType == "ad"` 永不渲染，不做占位。
2. 不新增开屏、插屏、横幅、信息流广告、激励视频、悬浮球。
3. `focus`/`square` 只在内容型条目（专辑/听单/直播）时渲染；营销活动位直接丢弃。
4. 不展示会员促销、充值、打赏入口；直播间不显示礼物面板。
5. 不使用“广告位留白”或“伪内容卡片”规避规则。
6. 验收：抓包/日志断言 `ad` 模块渲染次数为 0；UI 层无广告容器组件。

## 12. 设计决策记录

| ID | 决策 | 理由 | 被否方案 |
|---|---|---|---|
| D-01 | 顶级用 5 个 Tab，与官方一致 | 官方 `tabs` 接口即 5 项；Material 顶级 Tab 可横向滚动；层级最浅 | 抽屉 / 「更多」二级菜单：多一次点击，且隐藏核心域 |
| D-02 | 推荐不做无限流，用「换一换」/ 下拉刷新轮换 | 实测 `pageId` 只轮换（1/2 页 6 条中 5 条重复），追加会产生重复内容；整页替换语义一致（模块一起变） | 无限下滑：重复率 80%+，用户会认为卡住；只换单模块：同一 `pageId` 会让未换的模块与已换的模块错位 |
| D-03 | 卡片点击进详情，专辑页给主播放按钮；仅直播一键起播 | 误触播放有流量与打断成本（Nielsen #3 用户可控）；直播无选集，点击意图明确 | 卡片直达播放：误触率高、付费内容会频繁弹权限 |
| D-04 | 广告模块白名单过滤 | 用户硬约束；不把营销伪装成内容 | 保留但折叠：仍是广告 |
| D-05 | 城市模块默认不渲染，不申请定位 | 隐私最小化；定位权限收益低于成本（申请即弹窗） | 申请定位：拒绝率高，且 Lite 定位无其他用途 |
| D-06 | 个性化开关放设置，用匿名请求实现 | 官方无 opt-out 参数；匿名请求是唯一可控手段；隐私可解释 | 只做登录态：用户无法关闭；或做假开关：不可接受 |
| D-07 | 模块级失败降级，不清空整页 | 推荐是拼装页，单模块失败不应连坐（Nielsen #9 帮助用户恢复） | 整页报错：一个模块挂掉导致全页不可用 |
| D-08 | 分类筛选用接口的 `categoryMetaDatas`，不自造筛选项 | 维度与取值随分类变化，写死会错 | 固定「免费/付费/完结」：覆盖不全且与官方不一致 |
| D-09 | 广播只展示直播中，结束即移除 | 已结束直播不可播放，留在列表是死链 | 灰置保留：点击必然失败 |
| D-10 | 缓存分层：推荐 10min / 分类树 24h / 榜单 30min / 直播不缓存 | 内容时效差异；直播过期即错误 | 全部不缓存：冷启动白屏；全部长缓存：直播显示已结束房间 |
| D-11 | 分类只做「网格 → 结果页」两层，跳过 5 分组层 | 分组仅 5 个且「有声小说」组只有 1 个分类，多一层没有信息增量；分类 chip 已能一屏扫完 | 分组 → 分类 → 结果页三层：至少多一次点击；或 28 个分类一条横滑：可发现性差 |

## 14. 验收标准

1. 发现页存在 5 个 Tab，默认「推荐」，切换后各自保持滚动位置。
2. 推荐首屏至少渲染 1 个真实模块；`ad` 模块渲染数为 0。
3. 专辑 ≤ 2 次点击进入播放（卡片 → 专辑 → 播放）；直播 ≤ 2 次点击开始播放。
4. 分类网格可进入任一分类；结果页支持子类/排序/筛选/分页；切换分类后子类与筛选重置。
5. 每个页面具备 Loading / Empty / Error / Edge 四态，且错误可恢复。
6. 断网冷启动显示缓存内容，不清空页面。
7. 关闭个性化后，推荐请求不含账号身份，缓存键切换。
8. 全流程无开屏、插屏、横幅、促销位。
9. 所有交互元素 ≥48dp，图标有 `contentDescription`，LIVE 有文字标识。
10. 直播态播放器隐藏进度/倍速/略过头尾（不适用控件不展示）。
